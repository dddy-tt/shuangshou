## 题目

基于 STM32F407ZGT6 的双手智能手语交互手套系统

---

## 摘要

本作品面向语言表达受限人群、居家康复训练辅助场景与老年护理辅助场景，设计并实现了一套基于 STM32F407ZGT6 的双手智能手语交互手套系统。系统以双手弯曲传感器数据为核心输入，结合姿态信息、蓝牙通信、本地桥接服务与 Web 可视化界面，实现了手语翻译展示、康复训练辅助反馈、护理状态展示和家电远控四类功能。硬件端以 STM32F407ZGT6 为主控，完成十路手指弯曲采集、蓝牙数据输出、DFPlayer 语音播报接口和多路软 I2C 外设预留；软件端构建了 `serial-mqtt-ai-bridge` 本地桥接程序与 `web-dashboard` 前端看板，实现了从手套数据到网页显示、AI 反馈和 MQTT 远控的完整链路。系统支持自定义手势保存、训练目标随机抽取、0.3 秒稳定区间识别以及 BLE 直连网页演示，可在比赛展示中直观体现“采集—识别—反馈—控制”的完整闭环。作品强调低成本、可扩展、便于演示与后续硬件联调，具有较好的应用价值与工程推广意义。

## 第一部分 作品概述、功能与特点

### 1.1 作品概述

本作品是一套“手套端 + 桥接端 + 网页端”三层协同的嵌入式交互系统。手套端负责采集双手手指弯曲信息，并预留 IMU、心率血氧、振动反馈和语音播报接口；桥接端负责统一接收串口、蓝牙或回放数据，完成协议解析、AI 反馈生成和 MQTT 控制转发；网页端负责可视化展示、训练交互、自定义手势管理和家电远控。系统强调比赛演示可落地性，既可以在纯 Mock 模式下稳定演示，也可以在接入真实手套数据后直接切换到实机联调模式。

### 1.2 应用领域

本作品主要面向以下四类场景：

1. 语言表达受限人群的基础沟通辅助。通过识别常用手势并在本地或网页端输出翻译文本，帮助用户表达“喝水、帮助、不舒服”等高频需求。
2. 手部康复训练辅助。系统可记录训练目标、显示当前动作完成情况，并结合本地规则或云端 AI 生成简短训练建议，适用于居家训练和课堂展示。
3. 老年护理与日常看护辅助。系统可展示心率、血氧、跌倒、SOS 等扩展状态，并为后续护理提醒和远程关注提供接口。
4. 智能家居交互控制。通过自定义手势触发灯光、风扇、插座等 MQTT 控制主题，提升行动不便用户的环境交互能力。

### 1.3 主要技术特点（400 字内）

本作品采用“STM32 固件 + 本地桥接服务 + Web Dashboard”协同架构，兼顾实时性、可扩展性和演示友好性。底层主控选用 STM32F407ZGT6，实现十路弯曲传感器采集、蓝牙数据输出、DFPlayer 语音接口和多路软 I2C 外设管理；中间层使用 Node.js 编写 `serial-mqtt-ai-bridge`，统一承接 WebSocket、AI 反馈、MQTT 远控及后续串口实机接入；上层使用 React + Vite 构建四模块看板，实现手语翻译、康复训练、护理监测和家电远控的统一展示。系统支持十指弯曲实时显示、Zero/Full 校准、自定义手势保存与命中检测、训练目标随机抽取、0.3 秒稳定判定防误触发，以及 MQTT 继电器控制链路。整体方案既能在无硬件条件下用 Mock 模式演示，又能逐步接入 BLE、串口和传感器数据，具有较好的工程收口能力。

### 1.5 主要创新点（200 字以内，逐点给出）

1. 采用“手套端 + 本地桥接 + 网页端”三层结构，将嵌入式采集、AI 反馈与可视化演示解耦，便于比赛快速展示。
2. 将十指弯曲数据、自定义手势训练、护理状态展示和家电远控整合到统一 Dashboard，展示链路完整。
3. 引入 0.3 秒稳定命中机制，降低手势抖动和单次波动带来的误触发。
4. 采用桥接端统一接入 DeepSeek、MQTT 和后续串口，不在前端暴露 API Key，具备更好的工程扩展性。

### 1.6 设计流程（200 字以内，可加重要图）

本作品按照“需求拆解—底层固件收口—前端演示搭建—桥接服务打通—硬件联调扩展”的路径推进。首先确定双手手语交互、训练辅助和远控展示三条主线；随后完成 STM32F407 固件主链路整理，确保弯曲采集、蓝牙输出和 DFPlayer 接口可编译、可接线；接着开发 Web Dashboard 与 Node.js bridge，建立 Mock 到实机可切换的演示系统；最后接入 BLE 实际数据、自定义手势、MQTT 控制和后续传感器扩展。

## 第二部分 系统组成及功能说明

### 2.1 整体介绍

系统由手套采集层、本地桥接层和网页应用层三部分组成。

1. 手套采集层以 STM32F407ZGT6 为核心，负责弯曲传感器采样、姿态模块与血氧模块接口管理、蓝牙数据输出及本地语音/振动扩展。
2. 本地桥接层由 `serial-mqtt-ai-bridge` 组成，负责 BLE/串口输入统一解析、WebSocket 实时推送、AI 反馈调用、MQTT 远控发布、自定义手势存储与命中逻辑。
3. 网页应用层由 `web-dashboard` 构成，负责多模块可视化、训练交互、自定义手势管理、状态展示与家电控制。

[框图待补：系统整体框图，建议画出 STM32、bridge、dashboard、MQTT 设备之间的关系]

### 2.2 硬件系统介绍

#### 2.2.1 硬件整体介绍

硬件系统采用“主控板 + 双手传感器 + 通信/执行外设”的结构。主控板为 STM32F407ZGT6 最小系统板，负责十路弯曲通道采集与通信调度。左右手各配置 5 路弯曲传感器，用于获取十根手指的弯曲状态；系统预留两路 JY61P 姿态模块接口，分别面向左右手姿态补充；预留 MAX30102 心率血氧模块接口，用于后续护理辅助监测。通信方面通过 JDY 系列蓝牙模块输出文本帧，便于网页直接通过 BLE 接入；语音侧预留 DFPlayer Mini 与喇叭接口；控制侧通过 ESP-01S + MQTT 继电器板实现家电远控演示。当前样机已在“弯曲传感器 + 蓝牙 + 网页 + MQTT 继电器”主链路上完成验证。

#### 2.2.2 机械设计介绍

机械结构采用“手套采集 + 外接主控/执行盒”的轻量化方案。传感器固定在手套手指背部，通过排线汇总到外部控制系统，减少了手背局部堆叠，提高佩戴灵活性。主控、蓝牙、桥接供电和外设接口可集中放置于桌面演示盒或腰挂盒中，便于比赛现场快速搭建和检修。当前阶段结构设计以原型验证和功能展示为主，重点保证传感器位置清晰、布线可维护、继电器与灯具控制直观可见。  

[实物照片待补：手套正面、手套背面、主控与继电器整体图]

#### 2.2.3 电路各模块介绍

1. **主控采集模块**：STM32F407ZGT6 通过 ADC1/ADC2 采集十路弯曲传感器数据，构成左右手十指 FLEX 输入。
2. **姿态与血氧接口模块**：预留三路软 I2C，其中两路面向左右手 JY61P，一路面向 MAX30102，为后续姿态与护理数据接入提供统一接口。
3. **蓝牙通信模块**：通过 USART3 输出 `FLEX|...`、`IMU|...`、`BRINGUP: ...` 等文本帧，供网页 BLE 页面和桥接服务使用。
4. **语音反馈模块**：通过 USART1 连接 DFPlayer Mini，支持本地语音播报和后续离线提示音功能。
5. **远控执行模块**：桥接服务通过 MQTT 向 ESP-01S 继电器模块发布 `ON/OFF` 主题，实现灯光等负载控制。

[插图建议：主控引脚分配图、蓝牙/继电器接线图、ESP-01S 继电器控制图]

### 2.3 软件系统介绍

#### 2.3.1 软件整体介绍（含 PC 端或云端）

软件系统由固件、桥接服务和前端看板组成。固件部分运行在 STM32F407 上，负责采集、封装和输出传感器数据，并保留手势识别、DFPlayer、振动和 bringup 诊断等主链路。桥接服务运行于本地 PC，使用 Express 提供 HTTP 接口，使用 WebSocket 持续向前端推送实时数据，同时管理自定义手势命中、AI 反馈、MQTT 控制和后续串口输入。前端 Dashboard 基于 React + Vite 构建，提供四大功能模块和 Sensor Monitor 监视界面；当 bridge 在线时优先接入真实数据，当 bridge 不在线时自动切回 Mock 模式，保证展示连续性。云端仅承担可选的 DeepSeek 文本反馈功能，不直接参与底层控制。

[插图建议：软件总体架构图，标出 STM32、BLE、bridge、dashboard、DeepSeek、MQTT]

#### 2.3.2 软件各模块介绍

1. **STM32 固件模块**
   - `main.c`：主循环调度与数据输出。
   - `flex_sensor.c`：十指弯曲采集与 DMA 快照保护。
   - `bringup_diag.c`：JY61P、MAX30102、ADC、识别状态诊断输出。
   - `bluetooth.c`：蓝牙文本帧收发与控制命令入口。
   - `dfplayer.c`：语音播报接口。
2. **桥接服务模块**
   - `server.js`：HTTP、WebSocket、AI 反馈与控制入口。
   - `frameParser.js`：解析 `BRINGUP / GESTURE / CTRL` 等文本协议。
   - `customGestureStore.js`：自定义手势的增删改查与持久化。
   - `mqttClient.js`：向继电器主题发布控制消息。
   - `aiFeedback.js`：DeepSeek 在线调用与本地回退。
3. **前端 Dashboard 模块**
   - 手语翻译：显示当前手势、翻译文本、置信度和历史记录。
   - AI 康复训练：训练目标、倒计时、识别结果、辅助反馈、训练统计。
   - 护理监测：心率、血氧、跌倒、SOS 及状态提示。
   - 家电远控：灯、风扇、插座、SOS 控制。
   - Sensor Monitor：十指实时弯曲、校准、BLE 状态、自定义手势训练辅助。

## 第四部分 总结

### 4.1 可扩展之处

本系统在结构上保留了较强的扩展能力。硬件层面，可继续完善 JY61P 和 MAX30102 实机链路，增加振动反馈、电池供电和更紧凑的可穿戴封装；软件层面，可继续扩充固定手势词库、增加更多训练模板、优化十指校准算法，并把 DFPlayer 本地语音、串口实机输入和更多 MQTT 设备纳入统一控制；平台层面，可将当前本地 bridge 扩展为云边协同结构，进一步支持远程数据记录、训练历史分析和多终端联动展示。因此，本作品不仅适合作为比赛样机，也具备继续深化为完整产品原型的基础。

### 4.2 心得体会（1000 字内）

本作品的完成过程让我们对“嵌入式系统不是单片机单点开发，而是软硬件协同工程”有了更深的认识。最初我们关注的是手势识别本身，认为只要把弯曲传感器接好、识别逻辑写出来，作品就能自然跑起来。但在实际推进中发现，一个能稳定演示、可继续联调、还能在比赛场景里清晰表达价值的系统，远不只是某个识别函数能跑通这么简单。  

首先，在底层固件阶段，我们遇到过典型的嵌入式工程问题，例如引脚冲突、蓝牙与调试通道共用、软 I2C 外设稳定性、ADC 采样有效性以及模块初始化状态不透明等。这些问题让我们认识到，工程调试能力与功能实现能力同样重要。因此我们专门引入了 bringup 诊断输出，把 JY61P、MAX30102、ADC、识别链路都转成可观察状态，先保证“看得见问题”，再逐步解决问题。  

其次，在系统演示层，我们没有停留在“串口打印几个数”这一层，而是继续搭建了本地 bridge 和网页 Dashboard。这样做的好处非常明显：一方面，前端界面可以让十指数据、训练状态、护理状态和控制状态变得直观，便于答辩展示；另一方面，bridge 让我们把 AI 反馈、WebSocket 推送、MQTT 控制、自定义手势和后续串口接入统一起来，极大降低了系统耦合度。通过这种方式，作品从单纯的手套硬件，变成了一个完整的“数据采集—状态分析—可视化—反馈控制”系统。  

再次，在功能规划上，我们也学会了控制节奏。对于比赛作品来说，并不是功能越多越好，而是要优先保证核心链路真实可演示。因此我们把工作重点放在十指弯曲显示、自定义手势训练、稳定命中判定和远控开灯这些“看得见、能证明价值”的功能上；而对于 IMU、血氧、语音等模块，则采取“接口先对齐、诊断先补齐、再逐个联调”的策略。这让整个项目推进更稳，也更符合实际比赛时间安排。  

最后，这次作品也让我们体会到工程文档和交接的重要性。随着功能逐步增多，仅靠聊天记录和临时口头说明已经很难保证后续修改不出错。因此我们持续维护项目状态文档、硬件联调清单、引脚矩阵和交接说明，这既帮助我们自己复盘，也让后续协作更高效。整体来看，本项目不仅提升了我们在 STM32、前后端联动、MQTT 控制和系统集成方面的能力，也让我们对“如何把一个想法真正做成可展示的工程作品”有了更系统的理解。
