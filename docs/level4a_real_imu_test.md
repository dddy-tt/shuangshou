# Level 4A：真实 JY61P 自动健康采集

## 范围与安全

本工具验证右手真实 JY61P 的 `I2C1 → jy61p.c → JY61P_Right → IMU/ACC` 路径。默认运行会复用 Level 3 的 Keil、唯一 ST-Link 探测、Flash/Verify/Reset/Run 工具，然后通过 USB-TTL（默认 COM15）静止采集 15 秒。

- 允许发送且只发送一次 `TEST:EXIT`，必须收到 `[TEST] MODE=REAL` 才采集。
- 禁止 `TEST:ENTER/FLEX/IMU/ACC/APPLY`。程序不会发送 BLE、MQTT 或继电器命令。
- 测试期间 JDY-23、ESP-01S 应断开，继电器负载保持断电；不运行报警动作测试。
- 默认不要求或触发任何手部/板卡运动。`--motion-check` 才会在人按回车后提示缓慢倾斜，不做跌落或剧烈摇晃。
- 左手 JY、协议字段、传感器量程及报警阈值均不在本测试范围内。

## 运行

默认自动构建、唯一 ST-Link 烧录校验复位、REAL 模式确认及 15 秒采集：

```powershell
python tools/glove_test/test_real_imu.py --port COM15
```

采集时间可设为 10–20 秒。`--skip-build --skip-flash` 可在明确需要复用板上既有固件时只采集；跳过 Build 时必须同时跳过 Flash，避免烧录旧 HEX。可传 `--keil`、`--programmer`、`--probe-serial` 指定工具/目标探针。

可选、需要真人配合的缓慢姿态变化检查：

```powershell
python tools/glove_test/test_real_imu.py --port COM15 --motion-check
```

远程协作可加 `--motion-duration 20` 将动作窗口延至 20 秒（允许 10–30 秒）；默认仍为 10 秒。静态采集不受影响。

动作阶段会先完成静态验收，再在**串口关闭期间**等待真人准备；按回车后重新打开串口并清空输入缓冲区，只将设定时长内的新鲜帧计入动作窗口。请缓慢倾斜约 30–60° 并缓慢回正，切勿跌落、猛甩或拉扯接线。

## 自动判定

脚本完整保留原始串口日志，再逐窗口统计，而不是按一帧通过。默认静态验收检查：

- 至少收到 `BRINGUP JY=1,JY_RET=0`，并在全窗口收集足够的 JY/JYDBG/IMU/ACC 样本；ONLINE 比率至少 90%。
- ACC 有效率至少 90%，ANGLE 有效率至少 80%；三种样本都必须出现。单个 `ANGLE_ZERO` 被单独计数，不当作 I2C 错误或立即失败。
- `ERR` 不超过驱动的连续离线阈值 3；`LAST` 只能使用 `0x1f` 内定义位。静态窗口仍要求 ACC/GYRO/ANGLE 累计 I2C 错误不超过 3；恢复失败必须为 0，恢复尝试最多 1 次。
- 已见样本的年龄不得是未初始化哨兵，最大 AGE 不超过固件 120 ms 新鲜度窗口。
- IMU/ACC 正式遥测为有限值且处于驱动合理量程；用 `ACC_RAW × 16/32768` 与相邻正式 ACC 对照，误差不超过 0.002 g。静止有效 ACC 的中位模长需在 0.5–1.5 g，允许桌面倾斜。
- `READS` 推导的读取速率至少 50 Hz；JY/JYDBG/ACC 最大内部遥测间隙不超过 2.5 s、IMU 不超过 1.5 s。
- 状态/valid 标志取值合法；栈至少观测两次，所有 `GUARD=1`、`FREE>0`；出现活动报警时立即停止并且不自动确认。

阈值用于当前样机的静止健康测试，不是医疗安全认证。若判定失败，先用日志区分启动探测、I2C 各寄存器读取、样本陈旧、遥测调度和原始/换算路径；没有原始数据证据时不改 scale。

可选动作验收另建独立窗口（默认 10 秒，可设为 10–30 秒），复用上述传感器健康检查；还要求 JY/JYDBG 所有采样均在线，至少一个姿态轴跨越 8° 且有至少 3 次相邻 0.5–60° 的连续变化。动作窗口使用按采集量归一化的 I2C 错误率；阈值和状态语义见下方“动作窗口 I2C 错误率复核”。错误率低不能覆盖离线、AGE 超限、无效数据、恢复风暴/失败、非有限值、运动不连续、活动报警或栈守卫失败。`summary.json` 分别保存 `metrics`（静态）与 `motion.metrics`（动作），不能用静态健康数据代表动作健康。

## 动作窗口 I2C 错误率复核（2026-09-27）

STM32 的一个 `READS` 周期各尝试读取 ACC、GYRO、ANGLE 一次，因此：

- `expected transactions = READS delta × 3`
- 单项错误率 = 对应 ACC/GYRO/ANGLE 错误增量 ÷ `READS delta`
- 总错误率 = 三项错误总数 ÷ `expected transactions`

动作窗口的总错误率和每一项错误率都必须不超过 **0.50%**；缺少可靠计数/分母也判失败。0.50% 是本样机当前的工程回归界限：它高于用户此前给出的 12/6000 = 0.20% 低比例示例（该分布为 ACC/GYRO/ANGLE=3/6/3），又低于本轮实际观察到的退化窗口 40/5157 = 0.776%。这不是通用可靠性或医疗安全阈值，后续应继续用更多硬件样本校准。静态窗口原来的累计错误数门槛不变。

动作状态区分为：

- `PASS`：各项功能健康条件通过，I2C 错误和恢复增量均为 0。
- `PASS WITH WARNING`：功能健康条件通过，但观察到低比例瞬时 I2C 错误或成功恢复；报告仍显示错误率与计数。
- `FAIL`：错误率超界或计数不可用，或任一功能健康硬条件失败。全过程 ONLINE、最大 AGE≤120 ms、有效率、有限值、运动连续性、无活动报警、栈 `GUARD=1` 等条件独立生效。

三次有效 20 秒动作窗口（均跳过 Build/Flash；另一次没有实际倾斜的窗口不纳入）：

| 窗口 | READS Δ / 预期事务 | ACC/GYRO/ANGLE 错误 | 总错误率 | ONLINE / ACC有效 / ANGLE有效 | max AGE | 恢复尝试/成功/失败 | Roll/Pitch/Yaw跨度 | 结果 |
|---|---:|---:|---:|---|---:|---:|---|---|
| 1 | 1900 / 5700 | 1/0/0 | 0.0175% | 100% / 100% / 100% | 2 ms | 0/0/0 | 146.58° / 21.03° / 23.89° | PASS WITH WARNING（有1次ACC瞬时错误） |
| 2 | 1887 / 5661 | 1/0/0 | 0.0177% | 95% / 95% / 95% | 412 ms | 1/1/0 | 117.95° / 23.64° / 13.38° | FAIL（全过程掉线、AGE超限；HALERR AF观察4次，错误连续值最高4） |
| 3 | 1719 / 5157 | 15/13/12 | 0.7756% | 95% / 95% / 90% | 25 ms | 5/4/1 | 48.45° / 10.40° / 8.46° | FAIL（错误率超界、恢复风暴且有恢复失败、全过程掉线） |

每项错误率（ACC/GYRO/ANGLE）依次为：窗口1 `0.0526%/0/0`，窗口2 `0.0530%/0/0`，窗口3 `0.8726%/0.7563%/0.6981%`。窗口3 HALERR 最近探测值为 `0/0/0/0`，窗口内 AF 位观察3次；不能用最后一帧清零掩盖窗口内错误。三次窗口的最小栈剩余均为3312 bytes，`GUARD` 均为1；均未见活动报警。

结论：按新规则，窗口1为带警告通过，窗口2和窗口3仍是硬失败，因此**Level 4A 尚未完成 STATIC + MOTION VERIFIED**。第三个有效动作之前有一次没有实际移动（跨度0.03°/0°/0°）的尝试，且一次非交互终端在动作提示处因 EOF 退出；二者都不计入三次有效动作窗口。该轮静态阶段通过。窗口3在实际移动时错误率显著上升，并出现 I2C 恢复失败，说明“只按绝对错误次数”确实不合适，但归一化后也不能把该次总线退化判为通过。当前只更新 PC 测试器、单测和本说明；未改固件、CubeMX、传感器驱动或接线。

## 本轮动作复测（2026-09-27，尚未通过）

> 以下记录的是本次率值复核前的历史测试。其动作 I2C 判定当时使用“累计错误数≤3”的旧规则，已由上文按事务数归一化的 0.50% 规则替代；历史观测到的离线、AGE、有效率、恢复及运动数据仍然有效。

- 首次使用旧脚本得到的动作 PASS 无效：脚本打开 COM15 后等待回车，串口积压旧数据被误算进动作窗口，且只检查角度跨度和最后 5 帧 ONLINE。原始日志显示实际倾斜期间仍有 I2C 错误和恢复计数增长。
- 已仅修正 PC 测试脚本和单测，没有修改/重编译任何固件源码。新脚本把真人准备提示移到串口打开之前，丢弃缓存，独立采集动作健康数据；补充连续变化、全过程 ONLINE、I2C/恢复/AGE/栈判定，并识别 HAL I2C `WRONG_START`（0x200）诊断位。
- 新脚本首次真实动作复测：静态窗口 PASS；动作 Roll -29.69–8.19°（37.88°）、Pitch -0.05–6.90°（6.95°）、Yaw -14.74–-8.29°（6.45°）。动作 ONLINE 100%，IMU/ACC 有限，最大 AGE 2 ms，栈最低剩余 3312 bytes、GUARD=1、无活动报警；但是 ACC/GYRO/ANGLE I2C 错误增加 3/1/1 次，共 5 次，超过当前 3 次阈值，动作 FAIL。恢复增量 0/0/0。原始证据：`artifacts/real_imu/20260927_223353_804883/`。
- 因错误与移动同步，尚不能区分接线受力和 I2C 通信裕量；需要先固定 JY61P 电源、地线、PB6/PB7 连线，缓慢倾斜整板后复测。**目前仅 STATIC VERIFIED，不标记 STATIC + MOTION VERIFIED。**

- 新增后的 Python 单测全量 51/51 通过；动作健康及连续性回归包括“角度变化但 I2C 错误超阈值必须失败”和“单点角度尖峰不能代表连续倾斜”。

- 正式 20 秒真人动作复测：静态窗口 PASS；动作 Roll -36.22–52.12°（跨度 88.34°）、Pitch 3.77–18.72°（14.95°）、Yaw -1.66–28.03°（29.69°），有限值且多帧连续变化。动作窗口 ONLINE 比率 90%，ACC 有效率 80%，ANGLE 有效率 85%，最大 AGE 982 ms；I2C ACC/GYRO/ANGLE 错误增量 23/23/21，恢复尝试/成功/失败增量 15/8/7，`HALERR` 观察到 AF/NACK 位 11 次；栈最低剩余 3312 bytes，所有 GUARD=1，无活动报警。因出现离线、旧样本、I2C/恢复风暴，**动作 FAIL**；完整日志在 `artifacts/real_imu/20260927_224438_395116/`。

## 本轮真机结果（2026-09-25）

- 对比 I2C1 100 kHz 与 50 kHz。100 kHz 期间曾观察到在线率 87.5%、ACC/GYRO/ANGLE I2C 错误累计增加及恢复探测；另一个 15 秒窗口在线/样本有效率为 100%，但 GYRO 错误增加 23 次。因此单个短窗口不能代表稳定。
- 将右手 JY61P 所在的 I2C1 降为 50 kHz 后，保持 PB6/PB7、I2C 传感器地址、读取周期、数据比例和正式遥测格式不变；I2C2/I2C3 仍为 100 kHz。完整项目回归及随后独立 REAL 采集均通过。
- 15 秒 REAL 采集中确认 `BRINGUP JY=1,JY_RET=0`；JYDBG/IMU/ACC/STACK 分别收到 16/61/16/5 帧。ONLINE、ACC 有效率、ANGLE 有效率均为 100%，最大样本 AGE 为 2 ms，读取速率约 99.6 Hz；窗口内 ACC/GYRO/ANGLE I2C 错误、HAL 错误及恢复计数增量均为 0。
- 原始 ACC 与正式 ACC 不一致数为 0；静止重力模长中位数 0.9956 g。正式 IMU 有限且在量程内（该次静止读数 Roll=11.76、Pitch=10.66、Yaw=125.03）；最小栈剩余 3312 bytes，所有守卫值为 1。无格式错误、活动报警或虚拟模式。
- 结论限于本次硬件、接线和采集窗口：50 kHz A/B 结果消除了本次窗口内的错误，支持 I2C 通信裕量不足的假设，但不能单凭软件采集证明唯一物理根因。
- Level 4A 新增的 13 项 Python 单测通过；随后 `python tools/test_all.py --port COM15` 完整回归中 Python unittest 共 47/47，通过并得到 `PROJECT REGRESSION PASS`。详细原始结果保存在 `artifacts/real_imu/20260925_234914_648665/` 和 `artifacts/hardware_test/20260925_234816_417494_32504/`。
- `--motion-check` 未运行：静态健康验收不要求移动设备；如果要验证轴对慢速倾斜的响应，需另由人手动执行可选动作测试。

## 产物

每次结果写入 `artifacts/real_imu/<时间戳>/`：

- `serial.log`：命令方向和所有采集到的原始串口行。
- `build.log`、`flash.log`、`stlink_enumeration.txt`：实际工具调用证据（对应步骤执行时创建）。
- `summary.json`、`summary.txt`：样本统计、各项 PASS/FAIL、构建/烧录信息。

静态健康通过后，如用户需要确认角度轴对真实轻微转动有响应，再单独运行 `--motion-check`。全项目标准回归仍由 `python tools/test_all.py --port COM15` 执行；真实 JY 测试不被强制并入它。
