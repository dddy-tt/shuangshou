# 项目代理协作与额度控制

更新日期：2026-09-18。此规则替代此前“所有实现均由多子代理完成、Astra 全程重复审核”的工作方式。

## 默认工作流

1. 一个明确任务优先由一个 Luna 完成，模型 `gpt-5.6-luna`，推理强度保持 `max`。
2. Luna 读取必要文件，自行实现、定向测试、修复失败，交付文件清单和简短测试证据。
3. 普通文案、布局、局部业务改动不启动全项目重复审查；只核对差异与必要测试。
4. Astra 只在需求/架构决策、关键阶段验收、复杂未知问题和安全敏感修改时集中介入。
5. 报警解除、云端账号权限、继电器目标路由必须保留独立验收。测试通过不代表硬件或医疗有效性已验证。

## 减少无效消耗

- 默认单代理。仅对独立且写入范围不重叠的任务并行。
- 不让主代理和子代理重复阅读、实现同一任务，不将完整长对话复制给每个代理。
- 编辑时定向测试；最终一次相关回归与编译。代码未变化且无新失败证据时不反复重跑。
- 两次定向修复仍失败时提交最小复现和建议，由主代理判断下一步。
- 不为普通问题启动大规模审查流水线，不做无变化的状态轮询播报。
- 不自动提交、烧录、部署或驱动真实负载；Git 提交后必须告知版本号。

## Luna Max 与 Fast

用户级代理文件：`C:/Users/zxcvb/.codex/agents/luna-worker.toml.toml`。
保留现有文件名与角色名 `luna_worker`，避免造成重复角色或旧引用失效。

```toml
model = "gpt-5.6-luna"
model_reasoning_effort = "max"
service_tier = "fast"

[features]
fast_mode = true
```

只配置该代理，不修改全局 `config.toml` 的模型或速度。Fast 请求是否生效须在重新加载后的新代理任务中核实；已有任务不会因此获得已验证的热更新。配置语法有效不等于后端已接受 Fast。

Fast 更快但更耗额度，不能承诺省多少。若要关闭该代理 Fast，可将 `service_tier` 改为 `default`、`fast_mode` 改为 `false`，保留 `max`。

日常直接使用 Luna 的方式：在客户端模型选择器选择 Luna、Max（Fast 可选）开始日常任务；需要关键验收时再切换 Astra。本文件和子代理配置不会自动改变当前主对话模型。
