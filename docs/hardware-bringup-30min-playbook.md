# STM32F407 双手手语手套硬件联调执行文档（30分钟版）

## 1. 文档目的

这份文档用于硬件到位后的第一次集中联调，目标不是一次把所有功能调到完美，而是用最短路径确认下面几件事已经打通：

1. STM32 固件能稳定输出串口数据。
2. `serial-mqtt-ai-bridge` 能收到真实传感器数据。
3. `web-dashboard` 能显示十指 FLEX、IMU、校准状态和自定义手势状态。
4. 自定义手势链路能够完成“保存 -> 命中 -> 提示/执行动作”。

## 3. 当前系统组成

当前系统分为 3 层。

### 3.1 STM32 固件层

- 主控：`STM32F407ZGT6`
- 传感器：
  - 双手 FLEX 共 10 路
  - 右手 JY61P
  - 左手 JY61P
  - MAX30102
- 当前重点输出帧：
  - `BRINGUP: ...`
  - `FLEX|L1=...|L2=...|L3=...|L4=...|L5=...|R1=...|R2=...|R3=...|R4=...|R5=...`
  - `IMU|R=...|P=...|Y=...`

### 3.2 Bridge 层

目录：`serial-mqtt-ai-bridge/`

职责：

- 接收 STM32 串口数据
- 解析 `BRINGUP`、`FLEX`、`IMU` 等文本帧
- 提供校准接口
- 保存和匹配自定义手势
- 通过 WebSocket 推送给前端

### 3.3 Dashboard 层

目录：`web-dashboard/`

职责：

- 显示十指原始值和归一化值
- 显示 IMU 姿态
- 执行 `Zero`、`Full`、`IMU Zero`
- 保存和管理自定义手势
- 展示翻译、训练、护理、家电远控状态

## 4. 当前代码基准接线方法

联调时统一以当前代码、`.ioc` 和已有联调文档为准，不以旧版说明图为准。

### 4.1 JY61P 接线

- 右手 JY61P：`PB6 -> SCL`，`PB7 -> SDA`
- 左手 JY61P：`PB8 -> SCL`，`PB9 -> SDA`
- 两个 JY61P 都需要正确供电和共地
- 如果模块支持模式切换，必须确认已经切到 I2C 模式

### 4.2 MAX30102 接线

- `PC6 -> SCL`
- `PC7 -> SDA`
- 电源与地线按模块要求接好

### 4.3 FLEX 十指接线

当前前后端协议已经按十指设计，建议按“左手 5 根 + 右手 5 根”固定编号：

- 左手：
  - `L1` 左手拇指
  - `L2` 左手食指
  - `L3` 左手中指
  - `L4` 左手无名指
  - `L5` 左手小指
- 右手：
  - `R1` 右手拇指
  - `R2` 右手食指
  - `R3` 右手中指
  - `R4` 右手无名指
  - `R5` 右手小指

如果你们现场已经有更明确的 ADC 通道编号表，就在接线表上再补一列“物理手指 -> ADC 通道”的对应关系，避免后面看数值时对不上。

### 4.4 蓝牙/串口接线

- `USART3`
- 当前调试链路使用 `PC10 / PC11`
- 用于输出 `BRINGUP` 和后续联调帧

### 4.5 DFPlayer 接线

- 当前主链路保留 DFPlayer
- 串口使用 `USART1`
- 联调初期先保证主链路稳定，DFPlayer 放到后面验证

### 4.6 振动电机接线

- 当前以 `.ioc` 和代码为准
- `TIM4 -> PD12 / PD13`
- 当前只有 2 路，不是旧文档中的 4 路

### 4.7 接线总原则

1. 所有模块必须共地。
2. 先断电接线，再上电测试。
3. 先接核心链路，再接可选外设。
4. 每接完一类模块就做一次最小验证，不要全部接完再一起查错。

## 5. 接线完成后的基础测试方法

这部分最重要，建议现场严格照做。

### 5.1 上电前检查

1. 检查 VCC 和 GND 是否反接。
2. 检查 I2C 的 SDA、SCL 是否交叉接错。
3. 检查 FLEX 是否有虚焊、断线、松动。
4. 检查所有模块是否共地。

### 5.2 上电后先测 STM32 串口

烧录当前固件后，打开串口工具，观察是否持续输出：

```text
BRINGUP: JY_R=1,JY_L=1,JY_R_RET=0,JY_L_RET=0,MAX=1,ADC1=1,ADC2=1,DEG=1
```

通过标准：

1. 能稳定看到 `BRINGUP`
2. 右左 JY 在线状态有值
3. `JY_R_RET`、`JY_L_RET` 有返回码

### 5.3 测十指 FLEX

观察是否能输出类似：

```text
FLEX|L1=1210|L2=1188|L3=1225|L4=1196|L5=1201|R1=1298|R2=1312|R3=1285|R4=1301|R5=1279
```

测试方法：

1. 双手自然放松，记录一组初始值。
2. 单独弯曲某一根手指，确认对应编号数值明显变化。
3. 左右手依次做一次，确认 10 根都能对上。

通过标准：

1. 十个位置都有值，不是 `--`
2. 弯曲对应手指时，能看到对应通道变化
3. 不是所有手指一起完全同步变化

### 5.4 测 IMU

观察是否能输出：

```text
IMU|R=10|P=5|Y=90
```

测试方法：

1. 手套保持水平，记录初值。
2. 缓慢翻转、抬起、旋转手掌。
3. 观察 `roll/pitch/yaw` 是否跟着变化。

通过标准：

1. 数值不是长期固定不变
2. 改变姿态时有明显响应

### 5.5 测 Dashboard

启动前后端后，在浏览器打开：

```text
http://localhost:3000
```

重点看 `Sensor Monitor`：

1. 十指 raw 数值是否显示
2. 十指 normalized 是否显示
3. IMU 是否实时刷新
4. `Zero`、`Full`、`IMU Zero` 是否可点击

### 5.6 测校准按钮

1. 手掌自然放松，点 `Zero`
2. 尽量握紧，点 `Full`
3. 把手放到定义的参考姿态，点 `IMU Zero`

通过标准：

1. 放松时 normalized 更接近 0
2. 握紧时 normalized 更接近 1
3. IMU 清零后当前姿态更接近参考零位

## 7. 30 分钟联调流程

建议按顺序执行，不要一开始同时打开所有功能。

### 阶段 A：0 到 5 分钟

先确认 STM32 本体活着。

1. 用 Keil 重新编译并烧录
2. 打开串口工具
3. 检查是否稳定输出 `BRINGUP`

### 阶段 B：5 到 10 分钟

确认真实传感器文本帧已经出来。

1. 检查 `FLEX|...`
2. 检查 `IMU|...`
3. 用手指和姿态动作验证数值变化

### 阶段 C：10 到 15 分钟

确认 bridge 收到真实数据。

1. 启动 `serial-mqtt-ai-bridge`
2. 检查 [health](http://localhost:8765/health)
3. 确认 dashboard 不再只是 mock

### 阶段 D：15 到 20 分钟

做第一次校准。

1. 放松双手点 `Zero`
2. 握紧双手点 `Full`
3. 摆到参考姿态点 `IMU Zero`

### 阶段 E：20 到 25 分钟

录入第一批自定义手势。

建议至少录入 3 类：

1. 翻译类
2. 控制类
3. 训练类

### 阶段 F：25 到 30 分钟

验证命中和联动。

1. 重做保存时的手势
2. 看是否命中对应自定义手势
3. 看是否出现提示或对应动作状态变化

## 8. 接线后的专项测试建议

如果现场时间够，建议再做下面这些单项测试。

### 8.1 JY61P 专项测试

1. 只固定手掌不动，观察姿态稳定性
2. 分别测试右手和左手
3. 看是否存在一侧正常、一侧完全无数据

### 8.2 FLEX 专项测试

1. 每根手指单独弯一次
2. 记录“哪根手指对应哪个编号”
3. 发现编号错位时马上修正接线记录

### 8.3 MAX30102 专项测试

1. 先确认上电正常
2. 再看 `BRINGUP` 中 `MAX` 状态
3. 后续再做佩戴测试

### 8.4 蓝牙/串口专项测试

1. 确认电脑端能稳定接收数据
2. 确认不会间歇断流
3. 确认 bridge 串口配置和 STM32 波特率一致

### 8.5 振动电机专项测试

1. 分别触发两路
2. 确认电机都能震动
3. 确认不会因为供电问题带来系统掉线

## 9. 现场异常速查

### 9.1 看不到 `BRINGUP`

优先检查：

1. STM32 是否真的在跑程序
2. `USART3` 是否接对
3. 串口波特率是否正确
4. 蓝牙或串口模块是否供电正常

### 9.2 `BRINGUP` 有，但 `JY_R=0` 或 `JY_L=0`

优先检查：

1. 对应 JY61P 供电
2. 对应 I2C 接线
3. JY61P 是否已切到 I2C 模式
4. SDA、SCL 是否接反

### 9.3 十指 FLEX 没显示全

优先检查：

1. STM32 是否真的输出了 `L1~L5`、`R1~R5`
2. 接线表是否和前端编号一致
3. 是否只有两路旧协议还没切成十路协议

### 9.4 IMU 一直漂

先做：

1. 固定手套不动
2. 重新点 `IMU Zero`

如果还漂，再检查：

1. JY61P 固定是否牢靠
2. 供电是否有噪声
3. 是否受到机械抖动影响

### 9.5 bridge 只有 mock，没有真实数据

优先检查：

1. `SERIAL_PORT` 是否正确
2. 串口是否被别的软件占用
3. 波特率是否一致
4. STM32 是否真的输出了文本帧

### 9.6 自定义手势误触发

先做：

1. 重新 `Zero`
2. 重新 `Full`
3. 重新 `IMU Zero`
4. 重新录入模板

## 11. 当前阶段结论

当前项目已经不是“从 0 到 1”的状态，而是“主链路已通，等待硬件实测收口”的状态。

更准确地说：

1. 前端可以运行
2. bridge 可以运行
3. STM32 联调协议已经基本确定
4. 十指 FLEX、IMU、校准、自定义手势的前后端链路已经具备

硬件到位后，主要工作应集中在：

1. 真实接线核对
2. 真实传感器校准
3. 自定义手势模板质量优化
4. 误触发和稳定性验证

也就是说，后面的重点应该是“联调和参数修正”，而不是再大改系统结构。
